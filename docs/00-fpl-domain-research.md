# FPL（Fantasy Premier League）游戏规则、规模与决策核心调研

> **用途**：One Move 产品的领域知识基线（Domain Baseline）。所有产品设计、Agent 工具契约与规则校验均以此文档为依据。
> **适用赛季**：2026/27（兼容 2025/26 起生效的核心新规）

---

## 1. 游戏规模与基本盘

- **全球玩家规模**：超过 **1,130 万** 注册玩家（实际截图可见 2026/27 赛季已达 `11,328,127` 名经理），是全球规模最大的免费足球范特西游戏。
- **核心玩法循环**：玩家扮演英超俱乐部经理，用虚拟资金组建 15 人英超球员阵容，根据真实英超比赛中的球员表现每周计分，与全球玩家及好友私人联赛（Mini-League）比拼总分。
- **核心节奏**：每轮比赛（Gameweek, GW）**开赛前 90 分钟**锁定（Deadline），锁定后本轮阵容、转会、队长、芯片均不可更改。

---

## 2. 阵容与硬约束规则（必须由确定性工具 100% 校验）

| 约束维度 | 具体规则 | 对 Agent 产品的意义 |
| :--- | :--- | :--- |
| **初始预算** | **£100.0m**（随赛季球员涨跌，全队总身价+银行余额会动态变化） | 买人时：`新球员价格 <= 银行余额(ITB) + 卖出球员卖出价` |
| **15 人位置配额** | 严格固定：**2 门将(GKP) + 5 后卫(DEF) + 5 中场(MID) + 3 前锋(FWD)** | 卖掉什么位置，就**只能**买回同位置球员；FPL 内球员位置开赛前钉死，赛季中不变 |
| **同队上限** | 同一支英超真实球队最多选 **3 人** | 转会或重构时极易踩雷，必须硬校验 |
| **每周首发 11 人** | 从 15 人中选 11 人首发，必须满足：**1 门将 + 至少 3 后卫 + 至少 1 前锋** | 其余 4 人坐替补席（1 名替补门将 + 3 名顺位替补），当首发未出场 1 分钟时按顺位自动替补 |
| **队长与副队长** | 每周指定 1 名队长（**得分 × 2**）和 1 名副队长（队长 0 分钟出场时顶替 × 2） | 队长选择是全赛季方差最大、收益最高的零成本决策（单赛季可差 80~150 分） |

## 3. 转会、免费名额（FT）、罚分与价格机制（玩家最易混淆区）

### 3.1 免费转会名额（Free Transfers, FT）与 -4 罚分
- **获取与累积**：每轮默认获得 **1 个 FT**；若本周不转会（Hold），未使用的 FT 可累积到下周，**上限为 5 个**（2024/25 赛季起从 2 个上调至 5 个）。
- **超额罚分（Hit）**：当周转会次数超出当前拥有的 FT 时，每多转 1 人直接从该轮得分中倒扣 **4 分（-4 pts）**。
- **注意区分“钱”和“名额”**：`Free` 指的是**免扣 4 分**，而不是买人不花英镑预算。

### 3.2 球员价格变动与“卖出价”折算规则
- **更新频率**：每天凌晨（英国时间约 01:30 / 北京时间约 08:30~09:30）统一更新 1 次，受全球玩家净买入/卖出量驱动（单日上限 ±£0.1m，单轮上限 ±£0.3m）。
- **涨价利润对半分**：
  - 买入后若球员涨价，卖出时官方只分给你**涨价利润的一半（向下取整到 £0.1m）**。例：£10.0m 买入，市价涨至 £10.3m，卖出价仅 £10.1m（赚 0.1m）。
  - 若球员跌价，亏损全额由玩家承担，卖出价等于当前市价。
- **公开 API 的数据边界**：
  - 公开 API 能拿到**今日市价**、**银行余额**、以及**赛季中途转会买进时的成交价**；
  - **唯一拿不到**的是第 1 轮开局初始阵容里“一直没卖过的老球员”的真实买入价，因此公开工具必须标注**“估算卖出价”并支持用户手动微调**。

## 4. 计分规则与 2025/26～2026/27 关键新规

### 4.1 基础计分
- **出场**：< 60 分钟 **+1 分**；≥ 60 分钟 **+2 分**。
- **进球**：门将 +10 / 后卫 +6 / 中场 +5 / 前锋 +4。
- **助攻**：全位置 **+3 分**。
- **零封（Clean Sheet，需出场 ≥ 60 分钟）**：门将/后卫 **+4 分**，中场 **+1 分**，前锋 0 分。
- **扣分项**：门将/后卫每丢 2 球 -1 分；黄牌 -1、红牌 -3、乌龙 -2、射失点球 -2。
- **赛后奖励分（BPS）**：每场表现最佳前 3 名额外获得 **+3 / +2 / +1 分**。

### 4.2 近两年新规（AI 知识库必须显式对齐，否则会按老经验误判）
1. **防守贡献分（Defensive Contribution / DefCon）**：
   - 后卫单场完成 **10 次及以上** 解围、封堵、拦截、抢断（CBIT）直接 **+2 分**；
   - 中场和前锋单场完成 **12 次及以上** 防守动作（含夺回球权 CBIRT）直接 **+2 分**（每场封顶 +2）。
   - *影响*：防守型后腰和忙碌中卫的下限大幅提高，不能再用“只看进球助攻”的老眼光评估中后场。
2. **每赛季两套芯片（Chips）**：
   - 4 个芯片：**Wildcard**（当周无限免费转会，永久生效）、**Free Hit**（仅当周无限免费转会，下周恢复原阵容）、**Bench Boost**（替补 4 人也计分）、**Triple Captain**（队长得分 × 3）。
   - 上半程（GW1~GW19）一套、下半程（GW20 起）解锁第二套，**上半程不用完不结转**（每轮最多用 1 个芯片）。
   - *(注：2026/27 赛季无 2025/26 赛季非洲杯期间的额外 5 FT 补偿。)*

## 5. FPL 决策的本质难点（为什么天然需要 Agent）

1. **信息分散且半结构化**：硬数据在 API，但决定“上不上场、会不会轮换”的关键信息散落在主帅赛前发布会、伤病更新和社区讨论里。
2. **多目标动态权衡**：没有唯一正确答案——要同时权衡即时得分 vs 未来 3~5 轮赛程拐点、单周 -4 扣分 vs 攒 FT、稳健保级 vs Mini-League 追分博弈（Effective Ownership / 差异化）。
3. **赛前极度敏感的时间窗口**：Deadline 前 2~3 小时常有突发伤停新闻，玩家需要能快速重新评估并做 What-if 推演的智能助手。
