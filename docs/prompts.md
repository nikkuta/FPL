# FPL Agent 协作指令与模版手册

> 本文件供**人类开发者/PM**按需复制使用，无需每次让 AI 全文阅读。AI 只需读取根目录的 `AGENTS.md`。

---

## 一、新会话启动提示词

每次开启新对话时粘贴：

```text
请先阅读项目根目录的 AGENTS.md 以及当前产品、架构与进度文档。

请先向我汇报：
1. 你理解的当前阶段与产品核心边界；
2. 目前已完成、未完成以及存在风险/待拍板的事项；
3. 你建议本轮只推进的一个最小目标；
4. 动手前需要我确认的问题。

在我确认前，不要生成或修改任何代码。
```

## 二、常用沟通模式指令

在对话中直接输入对应指令（或贴上说明），切换 AI 的工作模式：

### `/讨论`（只对齐方案，禁止写代码）
> 只讨论产品定义、Agent 边界或技术取舍。按「结论 → 关键理由 → 2~3个候选方案与取舍 → 你的建议 → 需我拍板的问题」输出。每引入一个技术概念，说明它解决什么问题、不用它的后果以及如何验证。

### `/拆解`（把目标拆成防许愿式的小步）
> 把已确认的目标拆成多个可独立验证的小任务。每个任务写清：目标、输入输出、预计改动文件、异常路径、验收方式。暂不编码。

### `/实现`（严格小步编码）
> 仅实现当前已确认的一个小任务。先输出下方【实施前确认卡】，等我回复“确认”后再改代码；完成后按【实施后汇报卡】交付，并运行测试。

### `/走查`（防黑盒，强制自己学会）
> 带我走查刚刚实现的代码：画出调用关系与数据流、标出确定性逻辑 vs 模型调用、指出一个面试官最可能追问的取舍，并向我提 2~3 个问题检查我是否真懂。

### `/测试`与`/故障注入`
> 围绕当前模块设计并实际运行正常、边界、失败三类用例。主动注入异常（API 超时、快照过期、模型输出非法 JSON、预算/规则冲突、重复执行），验证降级与错误提示。明确区分“已运行”和“未验证”。

### `/评测`（Agent Evals 专项）
> 针对当前 Agent 能力设计或运行评测：区分离线回放评测（历史 GW 快照集上的约束遵守率、工具准确率、“不动”判定合理性）与在线赛后评测，输出基线对比与 bad case 分析。

### `/复盘`（沉淀面试素材）
> 整理本模块的产品决策、技术取舍、踩过的 bad case、修复方式与评测证据，并列出**我能够诚实、清晰地在面试中复述的内容**（严禁把 AI 独立完成的工作包装成我的经验）。

### `/纠偏`
> 检查当前代码与设计是否偏离 `AGENTS.md`：是否出现不必要的技术堆叠、范围膨胀、假数据、隐藏 mock 或未经验证的结论，并给出最小纠偏方案。

## 三、任务启停模板（搭配 `/实现` 使用）

### 1. 单轮领任务提示词
```text
本轮只推进：【填写一个具体小目标】。

先不要写代码。请按“用户问题 — 输入输出 — 主流程与异常流程 — 确定性与模型边界 — 验收用例”与我确认方案。确认后再小步实现。
```

### 2. 实施前确认卡（要求 AI 在动代码前输出）
```text
本步目标：
本步不做什么（非目标）：
预计修改/新增文件：
输入与输出：
核心数据流：
异常处理与降级：
验收方式：
是否需要我确认后才开始：是
```

### 3. 实施后汇报卡（要求 AI 在改完代码后输出）
```text
本步实际完成：
修改/新增文件：
核心数据流与关键决策：
异常与降级路径：
实际运行过的验证（附结果）：
尚未验证或仍存在的风险：
我需要理解并能复述的内容：
建议的下一小步：
```
