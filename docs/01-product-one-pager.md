# One Move — 一页产品定义（Phase 1 · v0.2）

> **版本**：v0.3（结合领域与竞品调研对齐版）
> **状态**：已确认（Phase 0.1 基线）

---

## 1. 产品一句话定位

**One Move** 是一个以 **AI Agent 为决策大脑** 的 FPL（Fantasy Premier League）赛前决策工作台：Agent 主动诊断你的球队现状、自主调用数据与规则工具进行多方案推演与对比，给出**逻辑自洽、规则 100% 合法的本周最优行动建议**（含“不动”），支持自然语言追问与 What-if 假设重演，并通过赛后实际得分复盘持续校准决策质量。

---

## 2. 我们解决什么问题（痛点与差异化定位）

1. **看懂数据 ≠ 做出好决策**：传统工具（FFHub、FPL Review 等）堆砌大量预测分表格，玩家依然不知道自己球队当下最致命的问题是什么、本周该先动哪一步。
2. **规则与财务账算不清**：免费转会名额（FT）累积（上限 5 个）、超额 -4 罚分、银行余额与估算卖出价折算、同队最多 3 人、以及 2025/26～2026/27 新增的防守贡献分（DefCon）等规则极易算错，导致“买不起”或“白白扣分”。
3. **填补新一代 AI 竞品的空白**：
   - 区别于**官方 FPL Companion** 的“只给发散选项不帮拍板”，也区别于 **FPL Pulse** 的“大而全重看板 + 新闻滞后 2~3 小时”；
   - **One Move** 聚焦**赛前最后一公里**：提供**唯一收敛决策 + 即时粘贴突发新闻重演 + 多轮冲突拆解 + 透明推理与双轨 Agent Evals**，同时严守不编造数字、不自动提交的底线。

---

## 3. 目标用户与核心使用体验（Phase 1）

- **目标用户**：FPL 玩家（Phase 1 优先服务单用户自用与 AI Agent PM 作品集演示）。
- **准入方式**：**无需注册登录**，输入任意公开的 FPL `Team ID`（或粘贴官网球队链接自动提取）即可使用。
- **借鉴新一代 AI FPL 工具（如 FPL Pulse / FPL Companion / FPL.team）的核心体验**：
  1. **载入与全局体检**：输入 `Team ID` 后，拉取公开阵容、银行余额与转会历史（自动推算 FT，卖出价标为估算并支持手动微调）。Agent 主动完成一轮**球队体检**，点出当前核心隐患（如伤停、赛程拐点、替补浪费、闲钱过多、队长隐患）。
  2. **Agent 自主推演与拍板**：Agent 自主决定调用哪些工具查询候选球员、赛程与新闻，提出多个可行假设（包括**“不动”**、**调阵/换队长**、**1 笔转会**，或在手握 2+ FT / 多人伤停时评估 **2 笔转会**），经确定性规则工具校验合法性后，由 **Agent 综合权衡并拍板主推方案**（附关键备选对比与可折叠推理过程）。
  3. **What-if 自然语言追问与重演**：用户可随时质疑或提出假设（如“*如果我想留着萨拉赫、下周攒钱买哈兰德呢？*”、“*把这段主帅发布会新闻考虑进去*”），Agent 现场调用工具重新推演并对比差异；若约束相互冲突导致无解，Agent 明确指出冲突点并给出放宽建议。
  4. **HITL 人工确认**：用户自行决定是否采纳，并去 FPL 官网手动执行操作（本产品绝不自动提交）。
  5. **赛后复盘与校准**：本轮比赛结束后，记录用户实际采纳动作与真实得分，对比 Baseline（如“每周不动”）评估 Agent 决策表现。

## 4. 确定性与 AI Agent 的核心边界

| 分工层 | 职责定位 | 具体负责内容 |
| :--- | :--- | :--- |
| **AI Agent（决策大脑）** | **自主规划、情报理解、工具编排、权衡拍板** | 1. 主动诊断球队痛点，决定查询哪些球员/赛程数据；<br>2. 解析用户粘贴的非结构化赛前新闻（伤停/轮换风险）；<br>3. 提出候选方案（含“不动”），调用工具验证；当方案被规则驳回时，读取报错信息**自我修正并重试**；<br>4. 综合事实数据与机会成本，自主拍板最优解并组织诚实的人话解释；<br>5. 响应用户自然语言追问与 What-if 约束重演。 |
| **确定性程序（工具箱与护栏）** | **客观事实、硬规则校验、基线参考** | 1. 拉取并校验 FPL 公开 API 快照，自动推算 FT（上限 5 个）与可用预算（ITB + 估算卖出价）；<br>2. **硬规则校验（绝不妥协）**：预算上限、FT 与 -4 罚分计算、同队最多 3 人、位置人数（2/5/5/3），对齐 **2026/27 最新规则（含 DefCon CBIT/CBIRT +2 分与两套芯片机制）**；<br>3. 提供客观指标与参考基线（如近期状态、赛程难度、保留 FT 的参考价值）；<br>4. 赛后实际计分与评测指标统计。 |

## 5. Phase 1 明确边界（做什么 vs 不做什么）

### Phase 1 必须做（In-Scope）
1. **真 Agent 工具闭环**：具备多轮工具调用、校验失败自我修正、基于真实工具结果决策的能力，不做“固定公式算完让 AI 写文案”的伪 Agent。
2. **“不动”作为平等一等公民**：不强行为了显得有用而推荐折腾，也不刻意偏向不动；由 Agent 结合 FT 机会价值平等权衡。
3. **规则 100% 合法守护**：任何推荐方案必须通过确定性规则校验，AI 解释中的数字必须与工具返回值严格一致。
4. **决策工作台形态**：球队体检与状态卡（FT / 预算 / 扣分账清晰拆开）+ 主推决策与备选对比 + **可折叠的透明推理轨迹（View Reasoning）** + 按需追问与 What-if 推演 + 复盘记录。
5. **双轨评测体系（Evals）**：支持基于历史快照的离线回放评测（约束遵守率、工具调用与自修正准确率、“不动”决策合理性、防幻觉一致性）与赛后在线复盘。

### Phase 1 明确不做（Non-Goals）
- **绝不自动向 FPL 官方提交阵容或转会**（严守 HITL 边界）。
- **不做账号体系、登录注册与多租户权限隔离**。
- **不做官方账号/Cookie 绑定或浏览器插件抓真实买入价**（采用“公开数据估算 + 手动微调”）。
- **不做 Wildcard / Free Hit / Bench Boost / Triple Captain 等芯片的跨多周联合规划**。
- **不做全网实时新闻/社媒自动爬虫**（Phase 1 先支持粘贴新闻文本 + 样例输入）。
- **不强行引入 RAG、多智能体（Multi-Agent）或 MCP**。

---

## 6. Phase 1 成功标准（怎么算做成）

1. **真实 Agent 能力可感知、可验证**：面对不同球队状态与用户追问，Agent 能自主选择工具、提出合理假设、在触发预算/人数报错时自我修正，并给出逻辑通顺的拍板理由。
2. **零规则幻觉**：所有推荐方案 100% 合法；AI 解释中的价格、FT、罚分数字与工具输出完全一致。
3. **端到端闭环 + 双轨 Evals 可跑通**：能完整走通 `Team ID → 体检与 Agent 推演 → What-if 追问 → 确认记录 → 赛后复盘`，并能用离线回放评测集对比不同 Prompt/工具设计的效果差异。
